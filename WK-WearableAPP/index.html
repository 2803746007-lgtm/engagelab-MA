旅程 1｜新设备绑定：按配对进度提供帮助

首批上线设备绑定添加事件 · 观察后帮助 · App Push
设备已选好却尚未绑定，才需要补充帮助。教程随机型变化，配对中的用户不追加提醒，绑定成功后立即停止。

建议渠道：App Push ｜ 触发：设备绑定事件 ｜ 退出：设备绑定成功，设备 ID 等于本实例设备 ID

旅程编排示意图

全程提前退出：设备绑定成功，设备 ID 等于本实例设备 ID。

业务痛点
  • 手机蓝牙已连接，不代表 App 内绑定成功。
  • 未开始与尝试失败，需要不同帮助入口。
旅程组件配置
  • 开始 · 事件：进入设备添加流程：仅覆盖有稳定设备标识、机型及配对状态的流程。即时操作提示由 App 原流程提供，本旅程补位未完成人群。
    • 进入：进入设备添加流程，携带设备标识、机型、教程链接；排除已有绑定记录、退订及不满足项目年龄资格的用户。
    • 再次进入：多实例；并发 5，达到上限拒绝新进入；最短间隔 1 天，累计次数不限。同一设备同次添加仅报一次进入事件。
    • 提前退出：设备绑定成功，设备 ID 等于本实例设备 ID。
    • 转化统计：设备绑定成功；监听窗口 1 天；对象 ID 匹配本实例。收入统计不配置。
  • 等待事件 · 30分钟内完成绑定：监听设备绑定成功，设备 ID 等于本实例设备 ID；已成功由提前退出结束；超时进入可发送时间。
    • 绑定成功：进入「结束 · 配对中、已绑或状态无效」。
    • 超时未完成：进入「可发送时间 · 终端时区 09:00–20:00」。
  • 可发送时间 · 终端时区 09:00–20:00：终端时区 09:00–20:00；设备时区缺失回退项目时区。
  • 条件分支 · 本设备当前配对进度：按设备清单中设备 ID 等于本实例设备 ID 的同一元素判断；同时复核未绑定、服务联系资格及有效教程链接。
    • 未开始且资格有效：进入「App Push 通知消息 · 未开始：打开添加入口」。
    • 失败且资格有效：进入「App Push 通知消息 · 失败：打开机型教程」。
    • 其余：进入「结束 · 配对中、已绑或状态无效」。
  • App Push 通知消息 · 未开始：打开添加入口：使用机型与添加链接变量，缺机型名称使用“你的设备”；链接或资格缺失不发送。
  • App Push 通知消息 · 失败：打开机型教程：使用本机教程链接，提示“查看连接步骤”；不推断硬件损坏。
  • 结束 · 配对中、已绑或状态无效：无匹配设备、状态缺失或资格无效也走本分支。
  • 结束 · 本次绑定帮助完成：本次帮助结束；仅由新的合格事件再次进入。
预期效益参考
减少添加步骤中的中断，观察入组后 24 小时绑定完成率；提升幅度由对照测试确定。

旅程 2｜首次功能使用：回到本机适用的操作入口

首批上线首次使用绑定事件 · 设备匹配 · 应用内消息
绑定后的帮助落到本机可用的功能。手表、音箱和翻译设备各用自己的完成标准，用户做完就不再收到相同引导。

建议渠道：App Push 应用内消息 ｜ 触发：首次使用事件 ｜ 退出：设备解绑，设备 ID 等于本实例设备 ID

旅程编排示意图

全程提前退出：设备解绑，设备 ID 等于本实例设备 ID。

业务痛点
  • 绑定成功后，用户仍可能找不到功能入口。
  • 自动同步不能代表用户完成一次主动操作。
旅程组件配置
  • 开始 · 事件：设备绑定成功：按本次绑定固定设备与任务，不要求客户另建实时查询接口。
    • 进入：设备绑定成功，携带设备 ID、绑定时间、适用任务及入口；仅启用已有可靠完成回执的机型；进入过滤退订与项目年龄资格。
    • 再次进入：多实例；并发 5，达到上限拒绝新进入；最短间隔 1 小时，累计次数不限；同一绑定事件去重。
    • 提前退出：设备解绑，设备 ID 等于本实例设备 ID。
    • 转化统计：本机核心任务完成；监听窗口 1 天；对象 ID 匹配本实例。收入统计不配置。
  • 条件分支 · App 安装状态：已安装继续；未安装结束。安装未知也结束；重新安装后由新的合格业务事件进入。邮件在已安装用户中按内容与渠道资格选用。
    • 已安装：进入「等待 · 1个日历日」。
    • 未安装或未知：进入「结束 · 已完成、解绑或不适用」。
  • 等待 · 1个日历日：按终端时区等待至次日 00:00，随后由可发送时间控制白天发送。
  • 可发送时间 · 终端时区 09:00–20:00：终端时区 09:00–20:00；缺失回退项目时区。
  • 条件分支 · 本设备任务状态与资格：设备清单按同一元素匹配设备 ID；仍绑定、无已知异常、任务适配、未完成且联系资格有效才发送。状态与链接缺失结束。
    • 未完成且资格有效：进入「App Push 应用内消息 · 打开本机核心功能」。
    • 其余：进入「结束 · 已完成、解绑或不适用」。
  • App Push 应用内消息 · 打开本机核心功能：任务名称与链接由绑定事件或现有属性提供。App 展示前复核任务、绑定与同意状态；已完成不展示。健康数据不进正文。
  • 结束 · 已完成、解绑或不适用：异常设备结束本轮；由合格的同步中断事件进入同步恢复旅程，不在 MA 中直接启动另一条旅程。
  • 结束 · 首次功能帮助完成：该次绑定不再追加重复功能提醒。
预期效益参考
帮助用户完成本机核心操作，MA 统计消息后任务完成；D14 使用情况由独立对照分析。

旅程 3｜普通VIP购买：按浏览与付款进度承接

测试期扩展会员购买意向事件 · 最新覆盖 · Push / Email
只承接普通 VIP 的真实购买意向。浏览者看权益说明，已选套餐者回原入口，真实付款失败者看处理方法，不混用表盘单购与 AI 会员。

建议渠道：App Push / Email ｜ 触发：会员购买事件 ｜ 退出：普通 VIP 支付成功，权益包 ID 等于本实例权益包 ID

旅程编排示意图

全程提前退出：普通 VIP 支付成功，权益包 ID 等于本实例权益包 ID。

业务痛点
  • 不同付费商品混在一起，会给错权益说明。
  • 账单已支付或处理中，不应再次催付。
旅程组件配置
  • 开始 · 事件：浏览、选套餐或失败：三个事件为 OR，不使用任意付费事件判断普通 VIP 身份。
    • 进入：普通 VIP 页面查看、套餐选择或支付失败（OR）；携带权益包 ID、套餐、原购买入口与商品资格；进入过滤退订与项目年龄资格。
    • 再次进入：多实例最新覆盖；并发 1，替换最早；最短间隔 30 分钟，累计次数不限。新事件更新当前购买意向，支付成功按权益包匹配退出。
    • 提前退出：普通 VIP 支付成功，权益包 ID 等于本实例权益包 ID。
    • 转化统计：普通 VIP 支付成功；监听窗口 1 天；对象 ID 匹配本实例。收入统计不配置。
  • 等待事件 · 30分钟内支付成功：监听普通 VIP 支付成功，权益包 ID 等于本实例权益包 ID；成功提前退出，超时进入发送时段。
    • 支付成功：进入「结束 · 已购、处理中或无有效渠道」。
    • 超时未完成：进入「可发送时间 · 终端时区 09:00–20:00」。
  • 可发送时间 · 终端时区 09:00–20:00：终端时区 09:00–20:00；无设备的用户回退项目时区。
  • 条件分支 · 当前账单、权益与渠道资格：先排除已拥有对应权益、处理中、订单无效和数据缺失。当前权益与账单由客户现有属性维护，不只使用开始时的旧状态。
    • 合格Push承接：进入「App Push 通知消息 · 已选未付：返回原套餐」。
    • 合格Email承接：进入「Email 模板消息 · 权益说明或付款帮助」。
    • 其余：进入「结束 · 已购、处理中或无有效渠道」。
  • App Push 通知消息 · 已选未付：返回原套餐：已安装 App 且具有营销推送同意，发送原套餐链接；不新建订单。仅浏览但无合格邮箱、已有合格 Push 时也使用权益说明内容。
  • Email 模板消息 · 权益说明或付款帮助：仅浏览且邮件营销同意有效时解释权益；已选套餐而 App 不可用时以合格 Email 承接；真实失败只发纯服务付款帮助，须有对应服务联系资格。
  • 结束 · 已购、处理中或无有效渠道：无营销同意不发送权益推广；失败信息不明不发送付款失败通知。
  • 结束 · 本次购买帮助完成：单次帮助后结束，新合格意向才重新进入。
预期效益参考
减少套餐理解与付款步骤中的中断，MA 统计消息后支付；入组后 7 日支付率用业务订单作对照。

旅程 4｜同步恢复：区分连接异常与正常离线

测试期扩展使用恢复中断事件 · 设备匹配 · Push / Email
只帮助曾成功同步、现在有预期同步信号的设备。根据已有异常信息给连接步骤，没有证据时只给同步指南，不把离线等同停用。

建议渠道：App Push / Email ｜ 触发：使用恢复事件 ｜ 退出：设备同步恢复，设备 ID 等于本实例设备 ID

旅程编排示意图

全程提前退出：设备同步恢复，设备 ID 等于本实例设备 ID。

业务痛点
  • 离线使用与连接异常，需要不同解释。
  • 缺少当前证据时，故障判断容易误导用户。
旅程组件配置
  • 开始 · 事件：设备同步中断：只启用已具备中断判定的设备；从未同步的交首次功能使用，正常离线不生成中断事件。
    • 进入：客户现有系统上报设备同步中断；携带设备 ID、机型与帮助链接。覆盖范围、阈值与离线能力先确认；进入过滤退订与项目年龄资格。
    • 再次进入：多实例；并发 5，达到上限拒绝新进入；最短间隔 7 天，累计次数不限。同一设备同一次中断仅报一次进入事件。
    • 提前退出：设备同步恢复，设备 ID 等于本实例设备 ID。
    • 转化统计：设备同步恢复；监听窗口 5 天；对象 ID 匹配本实例。收入统计不配置。
  • 条件分支 · App 安装状态：已安装继续；未安装结束。安装未知也结束；重新安装后由新的合格业务事件进入。邮件在已安装用户中按内容与渠道资格选用。
    • 已安装：进入「可发送时间 · 终端时区 09:00–20:00」。
    • 未安装或未知：进入「结束 · 已恢复、无需帮助或资格无效」。
  • 可发送时间 · 终端时区 09:00–20:00：终端时区 09:00–20:00；无设备时回退项目时区。
  • 条件分支 · 本设备当前状态与渠道资格：设备清单按设备 ID 同元素复核；恢复、解绑、主动停用、正常离线、状态未知或无帮助链接结束。
    • 异常且Push可用：进入「App Push 通知消息 · 连接异常：查看重连步骤」。
    • 需帮助且Email可用：进入「Email 模板消息 · 查看本机同步指南」。
    • 其余：进入「结束 · 已恢复、无需帮助或资格无效」。
  • App Push 通知消息 · 连接异常：查看重连步骤：已安装且有服务推送资格、当前有可信连接异常时，发送本机重连入口；不包含原始健康数据。
  • Email 模板消息 · 查看本机同步指南：无明确故障证据，或 App 不可用但有服务邮件资格时，提供本机指南；不推断没电或设备损坏。
  • 结束 · 已恢复、无需帮助或资格无效：无法确认预期同步、无联系资格或数据缺失也结束。
  • 结束 · 本次同步帮助完成：不再自动追加第 30 天问答邮件；新的合格中断事件按再次进入规则处理。
预期效益参考
为可自行处理的连接问题提供步骤，MA 统计同步恢复；入组后 7 日恢复率按同设备业务记录比较。

旅程 5｜普通VIP续费：按权益使用与账单状态帮助

长周期观察会员续费周期事件 · 日期锚点 · Push / Email
续费理由来自本周期实际用过的权益。未用者先得到使用帮助；扣款失败直接给付款步骤，处理中只等待结果，自动续费不催重复购买。

建议渠道：App Push / Email ｜ 触发：会员续费事件 ｜ 退出：普通 VIP 退款，订阅 ID 与周期 ID 均等于本实例

旅程编排示意图

全程提前退出：普通 VIP 退款，订阅 ID 与周期 ID 均等于本实例。

业务痛点
  • 未用过权益的用户，缺少继续付费的理由。
  • 扣款处理中与真实失败，不能使用相同催付。
旅程组件配置
  • 开始 · 事件：月度付费周期开始：开始配置含本周期的订阅、日期与统计；使用状态按周期维护，不能被下一周期覆盖。
    • 进入：普通 VIP 月度付费周期开始；携带订阅 ID、周期 ID、到期日、权益包与使用入口，排除赠送体验、AI 会员、表盘单购、退订与不满足项目年龄资格者。
    • 再次进入：多实例；并发 5，达到上限拒绝新进入；最短间隔 1 小时，累计次数不限。同一周期事件去重；续费、退款、失败事件均按订阅 ID 与周期 ID 过滤。
    • 提前退出：普通 VIP 退款，订阅 ID 与周期 ID 均等于本实例。
    • 转化统计：普通 VIP 续费成功；监听窗口 5 天；对象 ID 匹配本实例。收入统计不配置。
  • 条件分支 · App 安装状态：已安装继续；未安装结束。安装未知也结束；重新安装后由新的合格业务事件进入。邮件在已安装用户中按内容与渠道资格选用。
    • 已安装：进入「等待至 · 周期开始后第3天」。
    • 未安装或未知：进入「结束 · 已完成、超时或资格无效」。
  • 等待至 · 周期开始后第3天：选开始事件的周期开始时间后 3 天；时间已过或为空即退出，不补发旧周期帮助。
  • 可发送时间 · 终端时区 09:00–20:00：终端时区 09:00–20:00，缺失回退项目时区。
  • 条件分支 · 本周期权益使用与展示资格：按订阅和周期 ID 同元素判断；退款、已续费、周期无效或状态缺失结束；未用、正常有效且应用内营销资格有效才展示。
    • 未用且可展示：进入「App Push 应用内消息 · 未用：打开已购权益」。
    • 其余有效周期：进入「等待至 · 本周期到期前3天」。
    • 周期无效：进入「结束 · 已完成、超时或资格无效」。
  • App Push 应用内消息 · 未用：打开已购权益：使用本周期已购权益入口；App 实际展示前复核周期、使用与同意状态。免费功能不算会员权益。
  • 等待至 · 本周期到期前3天：等待开始事件携带的到期日前 3 天；时间已过或为空即退出。
  • 可发送时间 · 终端时区 09:00–20:00：终端时区 09:00–20:00；所有临期消息在本节点之后。
  • 条件分支 · 本周期账单、使用与渠道资格：读取当前周期属性：已失败且服务邮件资格有效，直接付款帮助；正常有效按使用深度及营销同意选择渠道；处理中或无营销渠道等待结果；已续费、退款、状态缺失结束。
    • 未用且邮件同意：进入「Email 模板消息 · 未用：已购权益使用说明」。
    • 已用且Push同意：进入「App Push 通知消息 · 已用：权益回顾与订阅管理」。
    • 已失败：进入「可发送时间 · 终端时区 09:00–20:00」。
    • 处理中或无营销渠道：进入「等待事件 · 10天内等待本周期结果」。
    • 已完成或无效：进入「结束 · 已完成、超时或资格无效」。
  • Email 模板消息 · 未用：已购权益使用说明：邮件营销同意有效才发送；自动续费只给权益和订阅管理入口，未自动续费才给原续费入口。已用但无合格 Push、具有邮件资格时，以价值回顾承接。
  • App Push 通知消息 · 已用：权益回顾与订阅管理：已安装且营销推送同意有效；只引用本周期真实权益使用。链接按自动续费状态区分，不催重复购买。
  • 等待事件 · 10天内等待本周期结果：监听本周期续费成功或扣款失败；成功结束，失败进入付款帮助时段，超时结束。此节点只处理未来事件，进入前已有失败由上方账单分支直接承接。
    • 扣款失败：进入「可发送时间 · 终端时区 09:00–20:00」。
    • 成功或超时：进入「结束 · 已完成、超时或资格无效」。
  • 可发送时间 · 终端时区 09:00–20:00：终端时区 09:00–20:00；当前已失败分支和后续失败事件共用此时段。
  • 条件分支 · 本周期仍失败且可联系：同订阅、同周期的账单仍失败、非处理中、未退款，且当前时间不晚于到期后 7 天、服务邮件资格与链接有效才发送。日期用到期属性偏移比较。
    • 仍失败且资格有效：进入「Email 模板消息 · 真实失败：更新付款方式」。
    • 其余：进入「结束 · 已完成、超时或资格无效」。
  • Email 模板消息 · 真实失败：更新付款方式：纯服务付款帮助，返回原支付渠道；本周期最多一次，不混入优惠。客户必要账单通知已覆盖相同帮助时不重复启用本消息。
  • 结束 · 本周期帮助完成：本周期不重复发送；新付费周期由新的周期开始事件进入。
  • 结束 · 已完成、超时或资格无效：到期后 7 天关闭观察；退款提前退出。已成功事件若在等待开始前发生，由当前账单属性拦截。
